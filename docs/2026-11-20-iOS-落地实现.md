## 二、平台工程这一层做了什么

### 2.1 生成与改造

```bash
cd dsh_mobile
flutter create --platforms=ios --org com.example --project-name dsh_mobile .
```

`flutter create` 只补了 `ios/`（Android 侧一个字节都没动），随后有四处**必须手工改**：

| 改动 | 位置 | 为什么非改不可 |
|---|---|---|
| 部署目标 12.0 → **15.0** | `Podfile` + `project.pbxproj`（3 处） | Xcode 27 / iOS 27 SDK **最低只支持 15.0**。留 12.0 会直接报 `range of supported deployment target versions is 15.0 to 27.2.x`，且报错指向 `Pods.xcodeproj`，极易误判成业务代码问题 |
| `post_install` 强制抬升所有 pod 的部署目标 | `Podfile` | `file_picker` 拖进来的 `DKImagePickerController` / `DKPhotoGallery` 仍写 9.0/10.0，不统一抬升就是同一条 Target Integrity 错误 |
| 新增 `PlatformBridge.swift` 并挂进 Runner target | `ios/Runner/` + `project.pbxproj` | Swift 没有 include，文件不放进去等于没写（`flutter create` 之后新增的 `.swift` 不会自动加入编译） |
| `Info.plist` 全套权限与 ATS | `ios/Runner/Info.plist` | 缺 UsageDescription 时 iOS 不是抛异常，是**直接 SIGABRT 杀进程** |

### 2.2 部署目标定为 15.0 的代价

覆盖 iPhone 6s (2015) 及以后。对本 App 这类"开发者自建网关的远程控制台"没有实际
损失 —— 目标用户的手机不会比 2015 年更老。换来的是在现行 Xcode 上能编译。

## 三、七个通道的 iOS 实现对照

全部在 `ios/Runner/PlatformBridge.swift`，通道名与 Android 侧逐字一致，**Dart 侧
一行都不用改**（这是当初把原生能力做成 MethodChannel、而不是塞进业务层换来的红利）。

| 通道 | Android | iOS | 差异性质 |
|---|---|---|---|
| `dsh_mobile/secure` | AndroidKeyStore + AES/GCM 手工加解密 | **Keychain**，不做手工加密 | 见 §3.1 |
| `dsh_mobile/url` | `ACTION_VIEW` | `UIApplication.open` | 等价 |
| `dsh_mobile/file` | FileProvider + `ACTION_VIEW` | 缓存落盘 + `UIActivityViewController` | 见 §3.2 |
| `dsh_mobile/deeplink` | intent-filter | `CFBundleURLTypes` + `application(_:open:)` | 等价 |
| `dsh_mobile/foreground` | 前台服务保活 | **如实回 false** | 见 §3.3 |
| `dsh_mobile/share` | SEND intent | 需 Share Extension，本版未做，回 nil | 见 §3.4 |
| `dsh_mobile/widget` | RemoteViews 小组件 | 需 WidgetKit Extension，本版未做，回 false | 见 §3.4 |

### 3.1 凭据：为什么 iOS 反而更简单

Android 必须自己生成一把不可导出的密钥、自己写 AES/GCM，因为 Android 没有
系统级、按应用隔离的凭据存储。iOS 有 —— 就是 Keychain。所以 iOS 侧**一行加密代码
都没有**，直接把明文交给 Security 框架。

关键属性选择：

- `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`
  - 选它而不是 `WhenUnlocked`：网关重连可能由后台任务在锁屏状态触发，
    `WhenUnlocked` 会让那条路径读不到 token 而**静默失败**。
  - `ThisDeviceOnly`：不进 iCloud Keychain、不随备份迁移 —— 与 Android
    `allowBackup="false"` 的取向一致，凭据不该跟着备份跑。
- `service` 固定为 `com.example.dshMobile.secure`。**改它等于让所有老用户凭据"消失"**
  （新 service 下查不到旧项），是不该随手改的常量。

`ping` 探针会在 Keychain 里写一条临时项再删掉，确认真的可用（某些企业策略设备上
会拒绝写入），失败就回 false 让 Dart 侧降级到进程内存储 —— 降级契约与 Android 相同。

### 3.2 交付物：分享面板，而不是"按 MIME 派发"

Android 用 FileProvider + `ACTION_VIEW` 把文件丢给能处理该 MIME 的应用。iOS 没有
等价机制，标准做法是 `UIActivityViewController`（系统分享面板，内含"用某 App 打开"）。

两个易踩的坑已处理：
- **iPad 上 popover 必须给锚点**，否则 `present` 直接崩 —— 这是"只在平板上炸"的典型。
- 文件名要清洗：交付物名来自模型输出，可能带 `/`、`..` 等路径片段。

### 3.3 后台保活：iOS 上**做不到**，且不该假装做到

Android 靠常驻通知的前台服务让进程在后台活着，保持 WebSocket 不断。
iOS 的三种对应手段都不适用：

1. **后台音频**（`UIBackgroundModes: audio`）—— 业内常见的"放静音音频保活"，
   App Review 会按 4.2 / 2.5.4 直接拒，且极耗电；
2. **`voip` 推送** —— 只有真正的 VoIP 应用可用，同样要审核；
3. **`beginBackgroundTask`** —— 只买到约 30 秒，撑不住长连接。

所以 `startForeground` 在 iOS 上**如实返回 false**。这不是降级，是架构差异：
iOS 的离线提醒走**服务端 ntfy 推送**（与 Android 同源，`push_settings_view` 里配置），
进程被杀也能收到通知。WS 长连接只在 App 前台时保持，回前台重连由既有的
`handleAppResumed` 负责。

> 顺带一提：这也意味着 iOS 上**不需要** `UIBackgroundModes`，我刻意没有声明它 ——
> 声明了却在用不到的场景保活，是审核问询的高发点。

### 3.4 分享接入与桌面小组件：本版未做，但**如实降级**

这两项都需要**独立的 Xcode target**（Share Extension / WidgetKit Extension），
各自带 Info.plist、App Group 共享容器，是一次独立的工程改动，不属于"能不能跑起来"。
本版的处理是：

- `consumePending` 回 `nil`、`update`/`clear` 回 `false`；
- Dart 侧本来就是这么写的 —— `ShareReceiver` 把 null 当正常路径，`WidgetBridge`
  捕获异常后 `debugPrint` 忽略。

所以界面上**不会出现假的"已开启"**，只是功能不存在。要补齐的话，动手点分别在
`PlatformBridge.registerShare` / `registerWidget`。

## 四、Dart 侧改了哪三处（都是 iOS 上真实会错的 bug）

工程能编过不等于功能对。这三个是**只有跑到 iOS 上才暴露**的问题：

### 4.1 通知权限在 iOS 上恒为"已授权"

```dart
// 旧代码（notification_service.dart）
final granted = await _plugin.resolvePlatformSpecificImplementation<
    AndroidFlutterLocalNotificationsPlugin>()?.requestNotificationsPermission();
_granted = granted ?? true;   // ← iOS 上恒为 null，于是恒为 true
```

iOS 上 `resolvePlatformSpecificImplementation<Android...>()` 返回 null，
用户在系统弹窗点"不允许"后 App 仍认为一切正常，**界面不会出现任何提示**。

修法：按平台分支，iOS 用 `IOSFlutterLocalNotificationsPlugin.checkPermissions()`；
并且要在 `initialize()`（它会触发授权弹窗）**之后再查一次**，才能拿到真实选择。

### 4.2 iOS 上会去下载并"安装"APK

`UpdateService` 整条动线是 Android 的发布形态（`latest.json` 的 versionCode、
按 ABI 拆的 `.apk`、交给系统包安装器）。iOS 上运行的结果是：提示"发现新版本"→
下载 8MB 的 `.apk` → 弹分享面板让用户"用某应用打开一个装不上的文件"。

修法：新增 `UpdateService.apkUpdatesSupported`（iOS 恒 false），在 `check`、
`download`、`handToSystemInstaller` 三处拦截；`about_view` 改为显示
"iOS 版通过 App Store 更新"，而不是落到"读不到 latest.json"那个误导性分支。

### 4.3 请求头把平台写死成 Android

`User-Agent: dsh-mobile/x.y.z+N (Android)` 会出现在发布侧与网关日志里。
写错平台会让"这个 404 是谁打的"变成猜谜。改为按 `defaultTargetPlatform` 取真值。

> 用 `defaultTargetPlatform` 而不是 `Platform.isIOS`：后者依赖 `dart:io`，
> 在 widget 测试里会跟着宿主机（macOS）走，iOS 分支测不到。

## 五、本机工具链（复现构建所需）

项目钉死 Flutter 3.24.5，这带来两个 Apple Silicon 上的坑，记下来省得下次再踩：

| 坑 | 现象 | 解法 |
|---|---|---|
| Flutter 3.24.5 官方 macOS 包只有 **x86_64** | `Bad CPU type in executable` | `softwareupdate --install-rosetta --agree-to-license` |
| `flutter --version` 会 `git fetch --tags`（拉整个 Flutter 仓库标签） | 命令"卡死"，后续命令全部排队在 `Waiting for another flutter command to release the startup lock...` | 一律加 `--no-version-check` |
| Google 源下载限速 | 20 分钟只下 67MB | `FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn`（引擎包 2.6GB 几秒下完） |
| 系统 Ruby 2.6 装不上 CocoaPods（`nap`/`ffi`/`zeitwerk` 接连要求 Ruby ≥3.2） | 一路 `requires Ruby version >= 3.x` | `mise use -g ruby@3.3` 再 `gem install cocoapods`（预编译包，30 秒） |
| `pod install` 克隆 pod 源仓库时 GitHub 超时 | `fatal: unable to access 'https://github.com/...'` | 开代理；或临时 `git config --global url."https://ghproxy.net/https://github.com/".insteadOf "..."` |

⚠️ **代理的坑**：把 `http_proxy` 全局导出会让 `flutter test` 全红
（`HttpException: Connection closed before full header was received`）——
测试框架在 `127.0.0.1` 起本地 HTTP 服务驱动测试 shell，代理把它也劫持了。
必须同时设 `no_proxy=localhost,127.0.0.1,::1`。

推荐的本地环境脚本：

```bash
export PATH=$HOME/.local/share/mise/installs/ruby/3.3/bin:$HOME/tools/flutter/bin:$PATH
export FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn
export PUB_HOSTED_URL=https://pub.flutter-io.cn
export no_proxy=localhost,127.0.0.1,::1
export NO_PROXY=localhost,127.0.0.1,::1

flutter() { command flutter --no-version-check "$@"; }

flutter pub get
flutter analyze
flutter test
flutter build ios --no-codesign        # 只需验证能编过时用这个
```

## 五·五、CI：未签名 IPA 的构建与分发

`.github/workflows/build-ios.yml`（`macos-latest`）在 push 到 main / PR / 手动触发时：

1. 装 Flutter **3.24.5**（钉死，不是 `3.24.x` —— 见 pubspec 里 `speech_to_text` 的注释）；
2. 跑 `flutter analyze --fatal-warnings` 与 `flutter test`（与 Android 同一套门槛，
   避免"Android 绿、iOS 红"变成常态）；
3. `flutter build ios --release --no-codesign`，版本经三个 `--dart-define` 注入
   （与 APK 流水线同源，漏传会退回 `app_version.dart` 的兜底值）；
4. 打成两个 IPA 并挂到 Release：
   - `dsh-mobile-<ver>-ios-unsigned.ipa` —— 越狱机 + AppSync Unified 直接装，永久有效；
   - `dsh-mobile-<ver>-ios-adhoc.ipa` —— `codesign -s -` 伪签名，装完闪退时换这个。

**为什么 CI 不签名**：证书泄露等于任何人可冒用开发者身份签恶意 App；Ad Hoc 的
profile 还绑 UDID，每加一台设备就要改一次；而公开仓库的 fork PR 根本拿不到 secrets，
两条路径会产出不同形态的产物。所以 CI 只负责"证明能编过 + 给出可自签安装的包"，
真正的签名分发留在本地（见 §六）。

安装方式（越狱机）：

```bash
# 1) Sileo/Zebra 加源 https://cydia.akemi.ai/，装 AppSync Unified（选对应 rootless/rootful 版本）
# 2) 把 IPA 传到手机（AirDrop / iCloud / Filza WebDAV）
# 3) Filza 点开 IPA 安装，或命令行：
ipainstaller dsh-mobile-1.39.17-ios-unsigned.ipa
# 4) 若点图标闪退，改用 -adhoc.ipa；仍不行则 ldid -S /Applications/Runner.app/Runner 后 respring
```

> Release 里**同时**挂着 Android 的 APK 与 iOS 的 IPA，注意按平台下载。
> iOS 要求 **15.0+**（部署目标所限，低于这个版本装不上）。

## 六、下一步：真机与上架（需要你的账号）

以下步骤都需要 Apple 开发者账号，本机无法代办：

1. **改 Bundle ID**：现在是占位 `com.example.dshMobile`（与 Android 的
   `com.example.dsh_mobile` 同属占位级别）。需同步改三处：
   - `project.pbxproj` 的 `PRODUCT_BUNDLE_IDENTIFIER`（Runner 与 RunnerTests）
   - `PlatformBridge.swift` 里 `Keychain.service`（**改了等于老用户凭据失效**，
     如果还没上架就无所谓）
   - `Info.plist` 的 `CFBundleURLName`
2. **签名**：Xcode → Runner target → Signing & Capabilities → 选 Team，
   或命令行：
   ```bash
   flutter build ipa --dart-define=APP_VERSION=... --dart-define=APP_BUILD=... \
     --dart-define=APP_PACKAGE_NAME=com.example.dshMobile
   ```
   （三个 `--dart-define` 与 APK 那条流水线同源，见 `scripts/app-version.mjs`，
   漏了会退回 `lib/models/app_version.dart` 的兜底值。）
3. **改深链接 scheme**：`dshmobile` 是全局唯一的，两个 App 声明同一个 scheme 时
   系统不报错而是**随机挑一个打开**。上架前建议改成带自己前缀的，
   同时改 `lib/services/platform_services.dart` 里拼接的前缀。
4. **App Store 审核问询预案**：
   - ATS 开了 `NSAllowsArbitraryLoads` —— 审核会问。理由是"网关是用户自填地址的内网
     服务，无公网可信证书"，与 Android 侧 `network_security_config` 同因。
   - 未声明任何 `UIBackgroundModes`（这是好事，见 §3.3）。
   - 权限用途串必须与实际行为一致（已按真实功能填写）。
5. **推送**：离线通知走 ntfy，不依赖 APNs，所以**不需要**申请推送证书。
   如果以后想做原生离线推送，那是另一件事（要 APNs + 自建推送服务）。

## 七、iOS 与 Android 的能力矩阵

| 能力 | Android | iOS | 说明 |
|---|---|---|---|
| 多会话 / 流式对话 / 审批 / 提问 | ✅ | ✅ | 纯 Dart，两平台一致 |
| 语音输入 | ✅ | ✅ | `speech_to_text`，iOS 需麦克风+语音识别权限（已配） |
| 选图 / 拍照 / 选文件 | ✅ | ✅ | `image_picker` + `file_picker`，iOS 需相册+相机权限（已配） |
| 本地事件通知 | ✅ | ✅ | `flutter_local_notifications`，iOS 需授权（已修 §4.1） |
| 离线推送提醒 | ✅ ntfy | ✅ ntfy | iOS 上这是**唯一**可行的后台提醒方式（§3.3） |
| 凭据加密存储 | ✅ Keystore | ✅ Keychain | §3.1 |
| 打开交付物 | ✅ | ✅ | 分享面板（§3.2） |
| 深链接直达会话 | ✅ | ✅ | `dshmobile://open?session=` |
| 后台保持 WS 长连接 | ✅ 前台服务 | ❌ | 系统不允许（§3.3） |
| 系统「分享到」接入 | ✅ | ❌ 未做 | 需 Share Extension（§3.4） |
| 桌面小组件 | ✅ | ❌ 未做 | 需 WidgetKit Extension（§3.4） |
| 应用内更新 | ✅ APK | ❌ 走 App Store | 系统限制（§4.2） |
