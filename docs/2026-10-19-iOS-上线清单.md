# iOS 端上线清单（2026-10-19 现状评估）

> **结论先说**：当前仓库**没有 `ios/` 目录** —— Flutter 工程当初只生成了 Android。
> Dart 层本身是平台中立的（全仓没有 `Platform.isAndroid` 分支，四条原生通道
> `dsh_mobile/secure`、`/foreground`、`/share`、`/deeplink`、`/widget` 全部
> try/catch 降级），所以缺的不是业务代码，而是**平台工程 + 四个 iOS 等价实现**，
> 且必须在 macOS + Xcode 上验证。Windows 上无法编译、无法签名、无法验证。

## 一、Windows 侧已经确认的事实（不需要重做）

| 事实 | 证据 |
|---|---|
| Dart 层无 Android 硬分支 | `grep Platform.isAndroid lib/` 无命中（仅一条注释） |
| 凭据层可降级 | `SecureStore` 捕获 `MissingPluginException` → 进程内表；`isPlatformBacked=false` 时保留明文兜底 |
| 通知层已带 iOS 配置 | `InitializationSettings(iOS: DarwinInitializationSettings())` |
| 保活层可失败 | `enableBackground()` 捕获异常返回 false，UI 据此如实提示 |
| 小组件通道可缺省 | `WidgetBridge.push` 静默吞异常 |

## 二、必须在 macOS 上完成的事

### 1. 生成平台工程
```bash
cd dsh_mobile
flutter create --platforms=ios .
cd ios && pod install
```

### 2. 四个 Android 能力的 iOS 等价物

| Android 实现 | iOS 对应 | 工作量 | 备注 |
|---|---|---|---|
| `SecureStoreBridge.kt`（Keystore + AES-GCM） | Keychain（`SecItemAdd`，`kSecAttrAccessibleAfterFirstUnlock`） | 中 | Dart 侧接口不变；同一条 `dsh_mobile/secure` 通道，换原生实现即可 |
| `GatewayKeepAliveService`（前台服务保活） | **不存在等价物** | — | iOS 后台 socket 会被挂起。可行路线只有：接 APNs（需 Apple 开发者账号 + 自建推送服务）或接受"切后台即断，回前台重连"。后者与现有 `handleAppResumed` 已兼容 |
| 通知动作按钮（`AndroidNotificationAction`） | `UNNotificationAction`（flutter_local_notifications 的 `DarwinNotificationCategory`） | 小 | 三个动作 ID 保持一致：approve / deny / defer |
| `StatusWidgetProvider`（AppWidgetProvider + RemoteViews） | WidgetKit + SwiftUI | 大 | 完全另写；数据经 App Group 的 UserDefaults 共享，Dart 侧用 `MethodChannel` 写同一份 key |

### 3. Info.plist 必配项
- `NSMicrophoneUsageDescription`、`NSSpeechRecognitionUsageDescription`（语音输入）；
- `NSAppTransportSecurity`：网关局域网是明文 HTTP/WS，需要按域名/IP 例外（**不要** `NSAllowsArbitraryLoads`，那等于全局放开）；
- `CFBundleURLTypes` 注册 `dshmobile` scheme（ntfy 深链直达会话）；
- 自签证书场景：iOS 的 `badCertificateCallback` 走 `URLSession` 不受支持，
  **TOFU 这条路在 iOS 上需要换成服务端公开证书（Tailscale/反代）或系统级安装描述文件** —— 这是与 Android 最大的行为差异。

### 4. 签名与分发
- Apple 开发者账号（$99/年）；
- Bundle ID 与 `APP_PACKAGE_NAME` 的 Dart define 对齐；
- TestFlight 先发内测，审慎对待"企业内部分发"。

## 三、验收清单（Mac 上跑）

```bash
flutter analyze --fatal-warnings
flutter test
flutter build ios --no-codesign        # 先验编译
open ios/Runner.xcworkspace            # 真机/模拟器验证
```

真机必须验证：
1. 配对 + 局域网明文连接（确认 ATS 例外生效）；
2. 发送消息 / 收流式增量；
3. 审批卡片批准 / 拒绝；
4. 通知动作按钮（前台与后台各一次）；
5. 切后台 30 秒再回前台：连接应自动恢复（`handleAppResumed`）；
6. 小组件（若本期实现）：添加后能读到 `连接/执行/待审批` 快照。

## 四、建议的排期

1. **先做 Keychain + 通知动作**（1~2 天，Dart 侧零改动）；
2. **再决定后台策略**：不接 APNs 就把"后台即断"写进产品说明，别假装能后台收推；
3. **最后做小组件**（WidgetKit，3~5 天）；
4. 证书路径单独评估 —— 如果用户群体有 iPhone，建议把 iOS 的默认远程通道定为
   Tailscale/自有反代（公开证书），而不是自签 + TOFU。
