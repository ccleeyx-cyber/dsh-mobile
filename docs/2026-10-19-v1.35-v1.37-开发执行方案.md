## 全局约束（每个阶段开工前重读一遍）

1. **绝不重启 dsh web**。网关插件（`dsh-server-plugin/`）的改动写完不生效，直到
   用户自己重启。每个网关阶段完成后，把重启步骤明确交给用户，先做不需要重启的
   客户端部分。本方案的每个阶段都按「先客户端后网关」排过序，不要打乱。
2. **测试不污染真实数据**。只跑 hermetic（`npm test` / `flutter test`）；
   live/e2e/destructive 只在用户显式点名时跑。新增网关测试一律 mkdtempSync 隔离
   `DSH_HOME`，零真实网关调用；新增 Flutter 测试走既有注入缝（fake channel /
   `debugSet*`），不新建会话。
3. **发布流程（改版，README §3 的流程只在最后执行一次）**：
   - 开发期间**禁止 push main**。开工时创建功能分支
     `feature/v1.35-remote-ops`（基于 main），所有提交落该分支；日常验证只跑
     `npm test` + `flutter test`，不触发 CI；
   - 三个阶段 + 工程卫生全部完成、且两个网关重启停点（见下）都经用户验证后，
     才执行唯一一次发布：合并回 main → 改 `dsh_mobile/pubspec.yaml` 版本为
     `1.35.0` → 写 `CHANGELOG.md` 的 `[1.35.0]` 小节（按阶段分三段）→ push
     main → `scripts/await-apk.mjs <commit>` 等产物。版本号唯一真源是 pubspec，
     tag 不触发构建，不要打。
4. **每个新行为必须带一个钉住它的测试**。空操作修复类缺陷（注释声称已修、代码
   未生效）在本仓库历史上反复出现，测试是唯一防线。
5. **写代码前先读目标文件**。本方案给出的行号与函数名基于 v1.34.1，AI 执行时若
   行号漂移以函数名/符号检索为准；若函数已不存在，停下来报告而不是猜。
6. **网关改动只在 `dsh-server-plugin/lib/` 与 `tests/` 内**，不碰 DSH 宿主源码。
7. **明文 HTTP 端口（3088）的行为在 v1.35 过渡期内保持不变**——老 App + 老配置
   零回归是硬验收线，TLS 是新增端口不是替换。

## 阶段 1：安全隧道 + TOFU（功能分支 phase 1）

### 1.1 【网关】自签证书签发模块

- 位置：新建 `dsh-server-plugin/lib/tls.mjs`；证书落
  `$DSH_HOME/mobile-access/certs/`（跟随 store.mjs 的根目录解析方式）。
- 改法：
  - 用 Node 内置 `crypto.generateKeyPairSync('ec', { namedCurve: 'prime256v1' })`
    生成密钥 + 自签证书（`crypto.X509Certificate` 构造或引入极小依赖，**优先零
    依赖**：Node 22 可用 `crypto.createSign` 手写最小 X.509，若手写成本过高允许
    引入 `node-forge`，在 package.json 注明理由）；
  - 启动时 `ensureCertificate()`：无证书 → 签发并写盘（私钥 0600）；有证书 →
    读回校验；损坏 → 备份旧文件后重签；
  - 证书含 SAN（当前所有内网 IP + `localhost`），IP 变化时 SAN 过期重签——重签
    即指纹变化，会触发 1.4 的 TOFU 告警，这是预期行为，文档写明。
- 验收（`tests/unit/tls.test.mjs`，全部 mkdtemp 隔离）：
  - 首次调用产生证书文件且指纹稳定；二次调用读回同指纹；删除私钥文件后调用
    重签且旧证书被备份；私钥文件权限 0600。

### 1.2 【网关】TLS 监听端口

- 位置：`core.mjs` 的服务器启动路径（检索 `listen`）。
- 改法：
  - 新增配置项（读 env `BRIDGE_TLS_PORT`，默认 `3443`，`0` = 关闭）；
  - TLS 端口与 3088 共用同一路由/鉴权栈——实现方式优先「同一个 http server，
    用 `tls.createServer` 包一层 + `SNICallback` 不需要（单证书）」；若现有
    结构是 WS upgrade 挂在 http server 上，则起第二个 `https.createServer` +
    同款 upgrade 处理器，路由函数抽公共层，**禁止复制粘贴路由表**；
  - WS 在 TLS 端口上自然成为 WSS，不需要额外处理。
- 验收（`tests/unit/tls-listen.test.mjs`）：起真 TLS server（自签证书、随机端
  口、测试内自连），断言：HTTPS GET 鉴权路径 401 而不是连接失败；WSS 握手成
  功；3088 明文路径行为与改动前完全一致（对照既有用例零修改通过）。

### 1.3 【网关】配对码携带证书指纹

- 位置：`/pair/qr`、`/pair/info` 的响应构造处（检索 `pair/qr`）。
- 改法：响应 JSON 增加 `certFingerprint`（SHA-256 of DER，`sha256/` 前缀格式）；
  老客户端忽略未知字段，天然兼容。
- 验收：单测断言新字段存在且与 `tls.mjs` 计算的指纹一致。

### 1.4 【App】TOFU 指纹信任库 + 变更告警

- 位置：新建 `lib/services/cert_trust.dart`（存储走 `secure_store.dart` 的
  Keystore，key 按网关身份 + 通道 = `cert_fp::<gatewayId>::<lan|remote>`）；
  连接层在 `dsh_service.dart` 建连回调里挂指纹校验。
- 改法：
  - 依赖 `bad_tls_certificates` / handshake 处理：自签证书在 Dart 的
    `IOWebSocketChannel.connect` 下会抛证书异常——捕获后读证书指纹（`SecurityContext`
    + `onBadCertificate` 回调拿 `X509Certificate`），比对信任库；
  - 三态：无记录 → TOFU 写入 + 连接成功；匹配 → 直连；不匹配 → 断开连接 +
    全屏告警页（红色、写明旧/新指纹、时间），用户点「我认识这次变更」才更新
    信任库并重连，点「不信任」则断开并保留旧指纹；
  - 降级：Dart VM / 单元测试环境无真证书时（fake channel），信任库逻辑必须可
    独立单测（注入指纹比对函数）。
- 验收（`test/cert_trust_test.dart`）：三态各一条 + 多网关共存互不影响一条 +
  同网关 LAN 指纹变更不影响 remote 条目一条。`flutter analyze` 零问题。

### 1.5 【网关】cloudflared quick tunnel 托管

- 位置：新建 `dsh-server-plugin/lib/tunnel.mjs`。
- 改法：
  - 下载：固定版本号 + 官方 release URL + sha256 校验，落
    `$DSH_HOME/mobile-access/bin/`（参考 saya-ch 的做法：确认后下载、失败降级
    为打印手动安装指引，不阻塞启动）；
  - 启动：spawn `cloudflared tunnel --url https://localhost:3443`，解析 stderr
    里的 `trycloudflare.com` 临时域名，写入状态文件并广播给已连接客户端；
  - 生命周期：绑定宿主进程退出即 kill（`process.on('exit')` + 父子进程
    detached:false）；地址变化 = 旧进程死新进程起，广播新地址；
  - **隧道指向 TLS 端口（3443）**，这是 quick tunnel 能拿到公开证书的前提——
    cloudflared 边缘做 TLS 终结，到本机回环段由 cloudflared 加密，手机侧证书
    是 Cloudflare 的公开 CA，不触发 TOFU。TOFU 只管局域网直连场景。
- 验收（`tests/unit/tunnel.test.mjs`，用假 cloudflared 脚本）：解析临时域名、
  哈希校验失败拒绝启动、进程退出清理、地址变化广播。**不打真实网络**。

### 1.6 【App】远程通道配置 UI

- 位置：`views/settings/` 新建 `remote_access_view.dart`；`custom_settings_view.dart`
  首页加一枚 `SettingsNavCard`（放「连接与诊断」下方）。
- 改法：
  - 表单：远程地址（https URL）+ 说明文案（quick tunnel 地址易变、重扫二维码
    即可、无需重新配对）；
  - `models/server_config.dart` 扩 `channel` 字段（`lan` / `remote`），连接层
    切通道复用 token；
  - 连不上 LAN 时的提示条加「切换远程通道」动作（`InlineErrorBar` 形态，不是
    SnackBar）。
- 验收：`flutter test` 新增 settings 页用例（入口可点 / 表单校验 / 双档共存）；
  360dp 不溢出（照抄既有 360dp 用例写法）。

### 1.7 阶段 1 收口（停点 A，不发版）

- 本阶段全部提交已在 `feature/v1.35-remote-ops` 分支；commit message 带
  `phase 1` 前缀。
- 把**重启步骤**明确交给用户：重启 dsh web 使网关改动（1.1/1.2/1.3/1.5）生效。
  AI 不得代替重启。
- 用户重启后，AI 跑一轮手工验证清单并记录结果（不开 App 端 e2e）：
  - `curl -k https://localhost:3443/health` 返回健康；
  - 配对二维码含 certFingerprint；
  - 开启 tunnel 后 `trycloudflare.com` 可从手机浏览器打开配对页。
- 验证通过 → 继续阶段 2（仍在功能分支）。验证失败 → 修复后重走本停点，**不
  发任何中间版本**。

## 阶段 2：锁屏即时审批（功能分支 phase 2）

### 2.1 【网关】单次审批令牌（approvalToken）

- 位置：`core.mjs` 审批队列（L1001 附近的 `put/remove`）；新逻辑放
  `features.mjs` 审批事件产生处（L1180 附近）。
- 改法：
  - 审批入队时铸造 `approvalToken`：`crypto.randomBytes(24).toString('base64url')`，
    队列对象内存保存 **SHA-256 哈希**（明文 token 只出现在发给客户端的事件里，
    落盘/日志只有哈希）；TTL 15 分钟；
  - 新端点 `POST /api/mobile/approvals/decide`：body
    `{ approvalId, decision: 'approve'|'deny', approvalToken }`；校验链：
    token 哈希匹配 → 未过期 → 未消费 → 审批仍在队列；任一失败返回结构化错误
    （`expired` / `consumed` / `mismatch` / `unknown`，App 据此区分提示文案）；
  - 消费后幂等：同 token 同 decision 重复请求返回成功（带 `alreadyApplied: true`），
    同 token 不同 decision 返回 `conflict`；
  - **敏感审批不铸 token**：`danger-full-access` 级别或 readonly 设备策略要求
    回 App 确认的，事件里 `approvalToken: null`，通知不显示批准按钮。
- 验收（`tests/unit/approval-token.test.mjs`）：铸造/正常消费/过期/重放/篡改/
  重复同向/冲突反向/敏感不铸/readonly 不可 decide，各一条。

### 2.2 【网关】decide 端点接路由与广播

- 位置：`extensions.mjs` 路由表（照 L657-660 approval-presets 先例）+ 既有 WS
  广播通道。
- 改法：decide 成功后走既有审批答复路径（批准/拒绝落到引擎），并广播
  `approval_decided` 事件，让 App 内 UI 与电脑端同步。
- 验收：单测断言 decide 触发了与 App 内批准相同的下游调用（mock 引擎缝）。

### 2.3 【App】通知动作按钮

- 位置：`services/notification_service.dart`；模型扩
  `models/approval_request.dart`（`approvalToken` 字段，缺省 null 兼容老网关）。
- 改法：
  - Android 通知渠道升级为高优先级；审批通知带三个 `AndroidNotificationAction`：
    批准 / 拒绝 / 延后 15 分钟（延后复用既有本地延后逻辑，**不答复网关**）；
  - 动作点击走后台 isolate 或前台 service 调 decide 端点，结果显示为一条简短
    通知（「已批准 · 会话继续」/「该审批已过期」），错误分类映射 2.1 的结构化
    错误码；
  - `approvalToken: null` 的通知不带按钮，文案引导「请打开 App 确认（敏感操作）」；
  - 锁屏可见文案沿用既有脱敏口径（工具名 + 命令首行，不含参数全文）。
- 验收（`test/notification_action_test.dart`）：token 存在时有按钮 / null 时无
  按钮 / decide 调用参数正确 / 过期错误码映射到正确文案。真机端到端验证交
  给用户重启网关后做一轮（AI 不跑 live）。

### 2.4 阶段 2 收口（停点 B，不发版）

- 本阶段提交带 `phase 2` 前缀；hermetic 回归全绿后交停点。
- 把重启步骤交给用户（2.1/2.2 需重启生效），用户重启后跑真机验证：
  锁屏收到审批通知 → 通知栏点批准 → 电脑端会话继续 → App 内审批 dock 同步
  消失；计时目标 ≤10 秒。AI 不跑 live。
- 验证通过 → 继续阶段 3（仍在功能分支）。

## 阶段 3：运维台三件套（功能分支 phase 3）

### 3.1 【网关】Runbook 指令库

- 位置：新建 `dsh-server-plugin/lib/runbook.mjs`；数据落
  `$DSH_HOME/mobile-access/runbooks.yaml`。
- 改法：
  - YAML schema：`name / description / command / danger: low|high /
    confirmRequired: bool / outputTail: 30`；
  - 执行走**既有白名单命令通道**（复用 host-ops.mjs 的命令执行与安全守卫，
    不新开执行原语）；高危项强制 confirmRequired；
  - 端点：`GET /api/mobile/runbooks`（列表）、`POST /api/mobile/runbooks/run`
    （执行，返回尾 N 行摘要 + 退出码 + 耗时）；用户自编辑 YAML 即扩库，网关
    文件变化热重载（参考 extensions.mjs 的文件监听先例）；
  - 预置三条示例（部署验证看日志尾 / 服务健康检查 / git 状态速览），全部
    danger:low。
- 验收（`tests/unit/runbook.test.mjs`）：schema 校验 / 高危需确认 / 白名单外
    命令拒绝 / 输出截尾 / 热重载。**不执行真实系统命令**（mock 执行器）。

### 3.2 【App】Runbook 执行界面

- 位置：`views/` 新建 `runbook_view.dart`；入口放对话页「⋯」菜单（不占一级 tab）。
- 改法：列表卡片（名称 + 危险徽标）→ 点击 → 低危直接执行、高危弹确认（写明
  命令全文）→ 执行中状态 → 结果卡（退出码 / 耗时 / 尾 30 行，复用代码块组件

- 验收：flutter test 覆盖列表渲染 / 高危确认门 / 结果展示，360dp 不溢出。

### 3.3 【网关】告警规则引擎

- 位置：新建 `dsh-server-plugin/lib/alerts.mjs`；状态落
  `$DSH_HOME/mobile-access/alerts-state.json`。
- 改法：
  - 规则（首版四条，全部网关侧已有数据源）：会话回合报错（事件流 error）/

- 验收（`tests/unit/alerts.test.mjs`）：四规则各触发一条 / 去重窗口 / 分级

### 3.6 阶段 3 收口 + 唯一发布 v1.35.0

阶段 3 提交带 `phase 3` 前缀。全部收口后按顺序执行**唯一一次发布**：

1. 最后一次全量回归：`npm test` + `flutter analyze` + `flutter test` 全绿；
2. 把阶段 3 的网关改动（3.1/3.3）重启步骤交给用户，用户重启后做阶段 3 的
   手工验证（runbook 执行一条 / 告警触发一条 / 小组件真机渲染）；
3. 验证通过后合并 `feature/v1.35-remote-ops` → main；
4. 改 `dsh_mobile/pubspec.yaml` 版本为 `1.35.0`，写 `CHANGELOG.md` 的

## 执行顺序速查（给 AI 的操作序）

```
开工：git checkout -b feature/v1.35-remote-ops（自 main）
1.1 tls.mjs → 1.2 TLS 端口 → 1.3 指纹下发        （网关，可连续做完）
1.4 App TOFU 信任库                              （App，不需重启）
1.5 tunnel.mjs → 1.6 App 远程通道 UI              （网关 → App）
1.7 停点 A：交重启步骤给用户 → 等用户验证（不发版）
2.1 approvalToken → 2.2 decide 端点               （网关）
2.3 App 通知动作                                  （App）
2.4 停点 B：交重启步骤 → 等用户真机验证（不发版）→ W-B 对账层重构
3.1 runbook → 3.2 App 界面 → 3.3 alerts → 3.4 收件箱 → 3.5 小组件
3.6 交阶段3重启步骤 → 用户验证 → 全量回归 →
    合并 main → 版本 1.35.0 + CHANGELOG → push main（唯一一次发版）
```

每个「等用户确认」是硬停点：网关改动生效与否只有用户重启后才能验证，AI
不得代替用户重启，不得在未验证前叠加下一阶段的网关改动，更不得中途发布——
**main 在整个开发期只接收最后一次 push**。
