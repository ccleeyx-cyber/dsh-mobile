## 0. 结论摘要

工程质量高于同类个人项目：分层清楚（服务/视图/网关 core·features·extensions）、
测试规模真实、注释记录了每次失败的根因、安全模型是 deny-by-default 而非白名单兜底。

真正的问题不在「写得糙」，而在三处系统性盲区：

1. **验证链条断在构建这一步**，并且被一个**事实错误的归因**（「本机无 Android SDK」）长期掩盖；
2. **可访问性与触控基线整批未做**（10-17 方案的第 4.1 阶段被跳过）；
3. **一个持续膨胀的 God service**（5884 行），是「改 A 坏 B」类缺陷的结构性原因。

## 2. 严重问题

### 2.1 🔴 「本机无 Android SDK」是事实错误，掩盖了真实阻塞

文档三处把「原生代码只能靠 CI 验证」归因于此：

- `CHANGELOG.md:32`（1.35.0 已知边界）
- `CHANGELOG.md:113`（1.35.1 桌面小组件后置的理由）
- `docs/2026-10-19-v1.35-v1.37-开发执行方案.md:4`

**实测事实**：

| 项 | 实际情况 |
|---|---|
| Android SDK | **存在**：`D:\android-sdk`，build-tools 35.0.0，platform-tools/adb 齐全 |
| 模拟器 | **存在**：`flutter emulators` → `dsh_test`（`~/.android/avd/dsh_test.avd`） |
| 真机 | 无：`adb devices` 为空 → 「无设备」这点成立，「无 SDK」不成立 |
| 真实阻塞 | 项目位于 `E:\workspace\个人`，**路径含中文** → AGP 8.1 拒绝 |
| `android.overridePathCheck=true` | **无效**：失败点后移到 Dart 前端 `Unable to read file: ...app.dill` |
| ASCII 路径 | **可以出包**：87.5s 成功，19.2MB |

**后果**：1.35.0/1.35.1 两版的「已知边界」建立在这个错误前提上；更实际的影响是
团队形成了「原生侧改动不本地验编译」的惯性，而本机完全能验。

**修法**：① 订正上述三处措辞，改为「工作区路径含非 ASCII 字符，AGP 拒绝构建；
需在 ASCII 路径或交由 CI」；② 需要验原生编译时，复制到 ASCII 目录构建后合回；
③ `dsh_test` 模拟器可用于无真机时的 UI 冒烟（REST 层）。

### 2.2 🔴 深色模式下角标白字几乎不可读

- 位置：`lib/views/main_shell.dart:135-148`
- 事实：徽章底 `color: context.c.warning`，文字写死 `color: Colors.white, fontSize: 9.5`。
  深色侧 `warningDark = #FBBF24`（`app_colors.dart:170`），白字压它对比度约 **1.65:1**，
  WCAG 正文门槛 4.5:1 的三分之一，也低于非文本 3:1。
- 后果：深色下「对话/工作区」tab 上的待办数字糊成一块白斑——而这是唯一的「有人在等你」信号。
- 修法：前景改 `context.c.surface`（与 `approval_card.dart` 已用对的写法统一）。

### 2.3 🔴 提问卡提交后可能永久禁用

- 位置：`lib/views/widgets/question_card.dart:67-74`
- 事实：`setState(() => _submitting = true)` 后**只在 `!ok` 时复位**；成功分支永不复位。
  卡片撤场依赖网关 `question_settled` 事件（注释明确不做乐观移除）。
- 后果：该事件一旦丢失（重连、切后台、网关重启都是常规场景），卡片永久停在
  「发送中…」+ 按钮禁用，用户不能重发也不能改答，而 agent 侧一直阻塞。
- 修法：`await` 真实结果或加超时（如 8s）后复位，并给出「没收到确认，可重试」出口。

### 2.4 🔴 工作区页把「未加载」渲染成「没找到」

- 位置：`lib/views/workspaces_view.dart:862-865`
- 事实：`filteredWorkspaces.isEmpty` 只有单一分支，文案固定「没有找到匹配的工作区」；
  全文件无 loading 状态（`isLoading` 命中 0），搜索词为空时同样显示这句。
- 后果：冷启动/断网时用户看到「没有找到匹配的工作区」，会读成「我的工作区丢了」，
  且页面没有转圈也没有重试入口。
- 修法：拆三态——加载中转圈 / 失败给错误条+重试 / 空搜索词说「还没有工作区」。

## 3. 交互与 UI

### 3.1 🟠 推荐问题插入不写草稿、不设光标

- 位置：`lib/views/chat_view.dart:877`
- 事实：`onInsertSuggestion: (text) => _inputController.text = text`。
  对照 `composer.dart:1907-1915` 的 `_appendSnippetTemplate`，那里多做了
  `updateDraft(...)` 与 `selection = TextPosition(offset: text.length)`。
  全项目其余 4 处写输入框的地方（`chat_view.dart:1723/2124/2130`、
  `composer.dart:1909-1913`）都成对调用 `updateDraft`，**只有这一处漏了**。
- 后果：① 文本不落草稿 → App 被系统杀掉/重启后丢失（切会话不会丢，
  `chat_view.dart:1926-1928` 会把它写回上一会话的草稿槽）；② 光标无位置，
  插入后要再点一次输入框才能接着打字。
- 修法：复用 `_appendSnippetTemplate` 的同一条路径（追加 + 光标到末尾 + 写草稿）。

### 3.2 🟠 chat_view 自身没按自己的文档改用 Selector

- 位置：`lib/views/chat_view.dart:701`（`Provider.of<DshService>(context)`，listen 默认 true）
- 事实：`lib/views/widgets/message_list_view.dart:5-15` 的文件头明确写了正确用法
  「`Selector<DshService, List<ChatMessage>>((d) => d.messages)`，这样 ChatView 自身
  只在列表身份变化时重建」，并说明抽该 widget 的唯一理由就是这个。
  但 ChatView 顶层仍是 listen:true；`dsh_service.dart` 有 **141** 处 `notifyListeners()`。
- 后果：流式期间每帧重建顶栏 + 全部横幅 + 整个输入卡片（含 `LayoutBuilder`、
  `_statusRows` 全量计算），而只有消息列表真的需要变。
- 修法：把 `ChatAppBar`/`ChatTopBanners` 的数据各自 `context.select` 收窄，
  或把 `ChatView.build` 拆成多个 Consumer 子树。

### 3.3 🟠 审批/提问 dock 的高度上限按「全屏」算

- 位置：`lib/views/widgets/chat_dock.dart:1071-1074`
- 事实：`maxHeight: MediaQuery.sizeOf(context).height * _dockMaxHeightFraction`；
  `sizeOf` 不随键盘缩小，而 chat 页 `chat_view.dart:779` 已设
  `resizeToAvoidBottomInset: false`，键盘由 composer 自己的 `Padding(bottom: viewInsets)` 消化。
- 后果：小屏 + 键盘时 dock 上限仍是全屏的 45%，与增高后的输入卡片叠加会挤压消息区，
  极端情况 RenderFlex 溢出（「审批卡出现时键盘弹起就破版」）。
- 修法：上限改为按 `height - viewInsets.bottom - 顶栏 - 输入卡片` 计算，
  或键盘打开时把比例降到 0.3。

### 3.4 🟠 MEMORY.md 编辑弹层固定 220 高且不可滚

- 位置：`lib/views/workspaces_view.dart:480`（`Column mainAxisSize.min`）、`:517-536`（`height: 220`）
- 事实：该弹层内 `SingleChildScrollView` 命中 0，编辑器与按钮都是固定高度。
- 后果：640dp 小屏 + 键盘时可用高度不足，必然溢出；1.3 倍字号更早触发。
- 修法：外层套 `SingleChildScrollView`，编辑器高度改 `min(220, 可用高度*0.4)`。

### 3.5 🟠 保存/审批按钮无 in-flight 防护

- 位置：`lib/views/workspaces_view.dart:556-571`（保存项目记忆）
- 事实：`onPressed: () async { await dsh.saveWorkspaceMemory(...) }`，无 submitting 标志；
  同文件「新建工作区」（`:185/205-208`）却有。`approval_card.dart` 的批准/拒绝同样没有，
  而 `chat_dock.dart` 的批量审批条明确有 `_busy`。
- 后果：弱网连点 = 两次 PUT / 两条 respond（第二条落 `alreadyGone`，界面像报错）。
- 修法：补「请求中禁用 + 转圈」，与项目已有写法对齐。

### 3.6 🟠 触控 44dp 基线整批被跳过

- 事实：10-17 方案 §4.1 计划建 `MinimumTouchTarget`；实测 `app_spacing.dart` 中
  **无此组件**，全 lib 引用 **0 处**。
- 现存小热区实例（已核实）：
  - `lib/views/workspaces_view.dart:1055-1063`：`Icon(Icons.copy, size: 13)` 裸套
    `GestureDetector`，未设 `behavior`，**命中区仅 13×13dp**；
  - `lib/views/widgets/turn_navigation_rail.dart:103-105`：18×14dp 轮次刻度
    （此项是**有意收窄**，见该处注释：rail 压在正文左缘会擦掉行首字，
    修法应是扩大命中区而不恢复底色，不能简单套 48dp）；
  - `lib/views/workspaces_view.dart:792-818`：搜索框固定 42 高，
    `suffixIcon` 的 `IconButton` 最小 48×48 会被裁切，且无 `tooltip`。
- 修法（低成本）：在 theme 里给 `TextButton`/`OutlinedButton` 统一
  `minimumSize: Size(44,44)` + `tapTargetSize: padded`，一处覆盖全 App；
  裸 `Icon` 热区至少包 44dp 的 `InkWell`。

### 3.7 🟠 `syncBeforeBuild` 在 build 期间触发 setState

- 位置：`lib/views/widgets/chat_scroll_controller.dart:277-284`（`onStateChanged()`）→
  `lib/views/chat_view.dart:74`（`setState(() {})`）
- 事实：该分支注释自称「仍在 build 期间执行」，条件为「用户在上方 + 尾部追加消息 + 浮钮未亮」。
- 后果：debug/测试下抛 `setState during build`；release 下静默多一帧重建。
- 修法：该分支改为 `addPostFrameCallback` 里再 `onStateChanged()`。

## 5. 架构与性能

### 5.1 🟠 dsh_service.dart 是 5884 行 God class

10-17 方案把它列为「阶段 7」，明确「独立分支长期做」，之后未执行，且仍在增长。

它同时承担：WS 连接/心跳/重连退避、HTTP 客户端、消息对账、取消栅栏、队列、
交付物、作业、统计、通知、加密通道、草稿。`notifyListeners()` 141 处。

这是多个历史缺陷的共同根因——例如三处消息解析漂移（方案 §1.4「轮询对账重建消息丢字段」）。
值得肯定的是类内部自文档极好（如 `_startSessionPolling:1886-1952` 解释轮询只作 WS 兜底、
从 700ms 降到 2.5s、`_sessionPollInFlight` 防重叠；`_cacheSessionHistory:546-565`
写明 LRU 6 条的理由），这让新人改得动——但不能替代拆分。

### 5.2 🟡 页面文件规模

`composer.dart` 2497 行 / 7 class、`session_info_sheet.dart` 2419 / 6、
`chat_view.dart` 2258 / 2、`chat_dock.dart` 1561 / 8。

### 5.3 🟡 markdown 清洗缓存容量偏小

`lib/widgets/safe_markdown.dart:87-99`：LRU=8，key 是整段正文；
流式消息每帧文本都变 → 每帧 miss 并挤出历史条目。
修法：上限提到 32–64，或对 `isStreaming` 的最后一条跳过写入。

## 6. 网关与安全

已核实做得好的部分（结论仍然成立）：

- 只读设备 **deny-by-default**：POST/PUT 一律视为写，靠显式例外表扩展
  （`lib/index.js:3487-3497`，注释记录了历史漏过三轮的清单）；
- token 比较 `sha256` + `crypto.timingSafeEqual`（`store.mjs:128-137`），
  配对 token 只存 hash（`:160-168`），撤销后拒绝；
- 鉴权爆破按 IP 退避，`/health` 这类最廉价端点也走同一套（`index.js:3058-3086`）；
- 审批令牌 24 字节 / 15 分钟 TTL / 只存 SHA-256；`danger-full-access` 下**不发令牌**，
  通知不出现批准按钮；
- 配对二维码内嵌一次性 6 位码而非长期 token；
- runbook **不过 shell**，管道/重定向/连接符一律拒绝；
- `catch {}` 的 15 处经逐条查看均为清理型（`req.destroy()`/`ws.close()`/
  `removeAllListeners()`），**未发现新的「引擎无此 RPC 却回成功」假接口**；
- App 侧 68 个端点全部有网关实现，0 个 404。

遗留的低危项：

- 🟡 未鉴权的 401 响应回显 `port` / `version`（`BRIDGE_VERSION`）/ 服务名
  （`lib/index.js:3097-3105`），可用于版本指纹；
- 🟡 主 token（`cfg.token`）是全局全权凭据且**不可经设备撤销失效**
  （`store.mjs:143-145`），撤销设备不影响它；轮换需手改配置。

### 第 8 项为何不做

`chat_view.dart:701` 的 `Provider.of<DshService>(context)` 要改成 `Selector`，
前提是把 `ChatAppBar` / `ChatTopBanners` / `ChatComposer` 都改成「自己按需订阅」的
组件 —— 这三个都是接收 `dsh` 整体入参的 `StatelessWidget`（`chat_dock.dart:65/528`），
收窄必须改它们的构造契约，等于把 2258 行的页面骨架重排一遍。

更关键的是：用「缓存子 widget 实例 + 参数相等则跳过重建」这类取巧做法，会引入
**陈旧 UI** 风险（顶栏停在旧状态），而这类「看起来没事的陈旧数据」正是本仓库历史上
反复吃亏的地方（1.32.0 消息缓存、1.35.1 小组件快照都为此写过注释）。因此这一项应当
按仓库既有纪律走独立分支 + 分步提交，而不是混在本次修复里。
