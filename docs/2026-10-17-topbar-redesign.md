# 会话页顶部布局改版方案

日期：2026-10-17 ｜ 起点版本：v1.29.2 ｜ 状态：**已实现，未发版（`pubspec.yaml` 的 version 未 bump）** ｜ 范围：`ChatAppBar`（顶栏）+ `SessionStatusStrip`（事件带）

对照图：`docs/2026-10-17-topbar-redesign.png`（源文件 `…-redesign.html`，改完随时重截）

---

## 1. 现状实测

| 区块 | 高度 | 内容 | 字号 |
|---|---|---|---|
| AppBar 工具栏 | 56 dp | 权限色点 7px + 会话名 + 执行中徽标 + 📁工作区 + 搜索 22 + 调节 22 | 13 / 9.5 / 10.5 |
| 状态条 | 34 dp | 6 组数字：轮步、tok/s、累计 tok、缓存命中、产出、改动、上下文、N 个在跑 | 11.5 |
| 分隔线 | 1 dp | `border` | — |
| **合计常驻** | **91 dp** | | |

851 dp 高的机器上，加上系统状态栏后顶部固定带占屏幕 **13.5%**，且这 91 dp 里**没有任何一档是"主"字号**——会话名 13 pt 只比状态数字大 1.5 pt，而右边是两个 22 pt 的图标。

## 2. 五个具体问题（都可复现）

**P1 · 同一事实说两遍。**「执行中」徽标在 `chat_dock.dart:183-205` 和 `session_status_strip.dart:463-493` 各渲染一次，同一会话运行时顶部会同时出现两枚样式不同的「执行中」。这是结构问题，不是视觉口味。

**P2 · 6 组数字在 360 dp 上必溢出。** 真机截图里状态条被硬裁在「改动」处，现在靠 14 dp 渐隐遮断（`session_status_strip.dart:511-535`）。渐隐是"承认溢出"的补丁；只要还在一条横滑容器里堆 6 组数字，这个问题会一直存在（代码注释自己也记了两次返工）。

**P3 · 触控热区不达标。** 状态条每段是 `InkWell` + `padding: 2/2`（`session_status_strip.dart:280-288`），实际热区约 18–20 dp 高。移动端最低 44 dp。

**P4 · 权限状态只有颜色编码。** `_getPolicyColor`（`chat_dock.dart:418-428`）用 success/accent/warning 三种颜色区分 `danger-full-access` / `auto-read` / `ask`，7 px 圆点、无文字。色觉障碍用户、以及深色模式下的低饱和场景都读不出来；更要命的是**全权执行和每次询问长得一样重要**。

**P5 · 左侧是空的，但返回行为已经存在。** `main_shell.dart:205-211` 的 `PopScope` 已经把"对话页侧滑返回 = 切到工作区 tab"实现了，可是顶栏左侧没有任何可见 affordance。用户能做的事，界面上看不出来。

附带：`13 / 11.5 / 9.5` 全是字面量，`app_spacing.dart` 已经明确要求按角色取 `AppText`，其中 9.5 还低于 `AppText.caption` 的 10.5 下限。

## 3. 三个方向

### 方案 A｜主栏收敛 + 事件带（推荐）

```
┌──────────────────────────────────────────────┐
│ ◯ 会话界面顶部布局改造        [搜索] [信息]  │ 48 dp
├──────────────────────────────────────────────┤
│ 📁 dsh_mobile          ●执行中  产出 3  23%  │ 32 dp（可整条不渲染）
└──────────────────────────────────────────────┘
```

- 主栏只回答一个问题：**我在哪个会话**。会话名升到 15/w600（`AppText.heading`），一眼可辨。
- 权限点从实心圆改成 **2 px 环**（空心＝还在问，实心＝全权），保留一眼可辨，同时不再和"运行中"的红点/蓝点混在一起。
- 第二行从「数字清单」变成「**事件带**」：只放**需要你现在反应**的东西，按阈值出现（见 §4）。常态不渲染，顶部就只有 48 dp。
- 49 dp 常态 vs 现在 91 dp：**省 42 dp**，360 dp 小屏上等于多读一整条回复。

### 方案 B｜折叠头（Sliver）

首屏 96 dp 给全部关键读数（轮步 / 上下文 / 产出），上滑收成 48 dp 单行。信息最全、滚动后最省，代价是要把 `ChatMessageStream` 从 `Column` 改成 `NestedScrollView + SliverAppBar`，且滚动位置与 `ChatScrollController` 那套状态机要重新对齐——**风险最高**，建议作为 A 的后续演进，而不是第一步。

### 方案 C｜原生即时通讯范式

左侧 44 dp 返回、标题两行、右侧单个入口、状态只剩一枚会呼吸的点。零学习成本、最耐看，但信息最少，且与"状态条"这套已有资产（信息面板入口、别处执行中）冲突最大。

### 推荐

**A 的骨架 + C 的左侧 leading。** 理由：

1. A 把"数字"和"事件"分开，正面解决 P1/P2；C 的 leading 一次解决 P5，且与已有的 PopScope 行为完全一致（点它 = 和侧滑返回同一件事）。
2. B 的收益（滚动省高度）在 A 下已经不需要——A 常态只有 50 dp 出头（实现后是 53）。
3. 三块的改动都局限在两个文件里，不需要动消息流和滚动状态机。

## 4. 实施结果（2026-10-17，未发版）

按方案 A 落地，并吸收了 C 的左侧 leading。以下是**代码里的实际值**，不是提议值。

### 落地后的几何

| 项 | 实测 | 说明 |
|---|---|---|
| 主栏 | 52 dp | 双行身份（15pt 行 + 11.5pt 行），`ChatAppBar.toolbarHeight` |
| 左侧入口 | 48 dp 宽 | 返回箭头 `chat-back-to-sessions`，与 PopScope 同一条动线 |
| 标题 | 15 / w600 | `AppText.heading`，单行、省略的是工作区不是它 |
| 第二行 | 11.5 | `●执行中 · 📁工作区 · 上下文 62%` |
| 右侧动作 | 2 × 48 dp 热区 / 22 图标 | 查找、会话信息（`chat-open-session-info`） |
| 事件带 | 36 dp（无事件时 1 dp） | 胶囊高 24，**整 36 dp 都是热区**；`SessionStatusStrip.rowHeight` |
| 常态合计 | **53 dp** | 旧版 91 dp → 省 38 dp；执行中/有未读产出时 88 dp |

### 与原提案的四处差异（都有原因）

1. **主栏 48 → 52，并且是双行。** 提案把「工作区」也放进事件带，但工作区必须在**不点任何东西**的情况下可见 —— 不同工作区可以有同名会话，从通知/深链接进来时这是唯一线索。塞进事件带就意味着"带上没别的事时看不到工作区"，所以它回到第二行。
2. **上下文占用留在第二行，没有 50% 门槛。** 它在第二行不额外占高度，没有理由藏；越过 70% / 85% 才换色（橙 / 红）。原来那条 2px 进度线随之删除 —— 颜色变化 + 输入框上方 85% 告警已经覆盖了同一件事。
3. **产出段只在未读时出现。** 这是"事件 vs 状态"最直接的体现：读过的产出不该继续占领顶部。于是「打开信息面板」的主入口回到顶栏那个 ⓘ 按钮 —— 事件带上的一段本来就不该兼任唯一入口（旧版正是这样，`deliverables: []` 时那段还会消失）。
4. **`N 个在跑` 留在事件带。** 提案写的是"只进信息面板"，但信息面板当前没有「其它会话」小节，挪走等于**丢功能**。先留在带上（它确实是"需要你知道"的事），等面板补上小节再搬。

### 改动的文件

| 文件 | 改动 |
|---|---|
| `lib/views/widgets/chat_dock.dart` | `ChatAppBar` 重写：双行身份、leading、`_PolicyRing`；`preferredSize` 改为与 `bottom` 实际高度一致（旧版写死 `kToolbarHeight`，而状态条另长 34dp）；删掉从未使用的 `onScrollToBottom` |
| `lib/views/widgets/session_status_strip.dart` | 「状态条」→「事件带」：去掉 counts / tokens / changes / context 四类参数与段落，胶囊化，热区由约 20 dp 提到 36 dp |
| `lib/views/chat_view.dart` | 传 `onBackToWorkspaces`（复用已有的 `onOpenWorkspaces`） |
| `test/widgets/session_insights_test.dart` | 事件带组重写（9 条）；集成组新增"执行中只出现一次""用量数字不在顶栏""360dp 最挤一帧不溢出"，两处面板入口改走 ⓘ，一处「产出 0」断言反转 |

`SessionStatusStrip` **没有**改名成 `SessionEventStrip`：它仍然是挂在 `AppBar.bottom` 上的那一条，改名会制造 30 处 diff 却不改变任何行为；语义变化写进了类注释。

### 验证

- `flutter analyze` → `No issues found!`
- `flutter test` → **760 passed**（改动前 762；事件带组从 14 条收敛到 8 条，集成组新增 3 条 + 1 条 360dp 回归）
- 新增的 360 dp 用例专门覆盖最挤的一帧：长会话名 + 长工作区 + 执行中 + 75% 上下文 + 未读产出。断言：无渲染异常、顶栏总高 ≤ 88 dp、执行中与上下文完整可见、被省略的只有工作区名。
- **未做**：真机截图。当前没有连接的设备，也没起模拟器；要看到真机效果需要 `flutter build apk` 装机。深色模式与 1.3× 系统字号同样只过了静态推断（颜色全走语义 token、字号走 `AppText`），没有真机确认。

## 5. 不建议做的

- **不要给顶部再加第三行**、也不要把字号往 9.5 以下压 —— 那是拿可读性换信息量，代价记在无障碍上。
- **不要把「会话信息」做成只能用图标长按的隐藏入口**。现在它是 48 dp 的按钮，触控已经达标，别退回小热区。
- **不要为了"整齐"给顶栏加 elevation 或阴影。** `scrolledUnderElevation: 0` 是刻意的：消息区底色 `surfaceMuted #F8FAFC` 与顶栏 `surface #FFFFFF` 已差一档，1 dp 分隔线够用；加阴影只会让 53 dp 变成"浮起的一张卡"，反而更重。
- **不要把轮/步、tok/s、缓存命中重新请回顶部**，哪怕用"只在执行中显示"这种理由。它们是明细，信息面板已经有一次到位的口径；顶部每加一组，就回到"34dp 里塞 8 组数字"的老路。
